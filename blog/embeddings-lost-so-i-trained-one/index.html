I trained a search model for RiverGuide and measured it against the keyword search it replaced, on 523 real student questions and RiverGuide’s 54-question test.

What I did

  • Took a small open search model, Qwen3-Embedding-0.6B.
  • Trained it for 40 minutes on one RTX 4090, with 31,000 practice questions about the college’s pages.
  • RiverGuide now searches the student’s question with it first, so the answering model usually answers in one step.
  • Runs on the CPU, about 150 ms a search. Live since 24 October. Free on Hugging Face; code on GitHub.

Against an LLM wiki

Same answering model, same 54 questions: the wiki got 49 right, mine got 50. Mine used 8,921 tokens a question to the wiki’s 16,767. Same accuracy, 47% cheaper.

How I measured. Accuracy: the first question from each chat students had with the college’s assistant, Sept 24 to Oct 24, 2026, counted as answered when one of the search’s top 5 pages answers it, judged blind by Qwen3.8-27B. Speed: median time to a full answer on RiverGuide’s 54-question test, through the real app, four questions at a time (tool calls fell from 111 to 75). Cost: tokens per question on the same 54 questions, one at a time, both searches in the same run.
