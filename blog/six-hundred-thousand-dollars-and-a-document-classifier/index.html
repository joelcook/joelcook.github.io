The $600k proposal and the filing problem

Years of documents, inconsistent filing, and a move from Workday to Banner. I built the classifier in-house.

12 Sep, 2026

The president of Indian River State College decided we were moving from Workday to Banner. New system, fresh start.

Except we had years of documents that had to come with us.

The filing hadn’t kept up with the volume. Documents had piled up in broad categories that said nothing about where they belonged in Banner. Changing systems meant dealing with all of that history.

One outside company’s proposal put the work at $600,000.

I built the classification software in-house instead. It prepares the document indexes, and that $600k proposal is the spending we avoided, which is where the savings number comes from. The job was to take a filing mess too big to look at and turn it into rules a person can read and an output the new system can actually use.

My favorite problem was two letters long.

DE can mean Dual Enrollment. It also shows up as “De” in people’s names. Get a little too eager with text matching and a student’s name turns into evidence about what kind of document they submitted.

Tiny bug. Now repeat it across an entire migration.

The good news: the evidence was already in the export. Filenames, paths, existing categories. I wrote Python rules around approved phrases and destinations, normalized the separators, and masked known names and IDs before any matching happened, including names that turned up elsewhere in the input. A filename had to say something about the document itself before it earned a placement.

When the evidence conflicted, the file went to an approved fallback. It’s tempting to keep pushing the specific-classification number up, because a bigger percentage makes a nicer dashboard. The person looking in the wrong folder later doesn’t care about the dashboard.

The documented sample run covered 1,887 index rows. 1,396 got a specific document type. 491 went to the approved Legacy Document destination. That’s a sample, not a claim that every document was inspected or that accuracy is 100%. And the run made zero LLM calls.

There is a model-assisted path. It can use a local model through Ollama, or a cloud backend if someone explicitly turns it on. Either way, the model sees redacted inputs and its suggestions wait for a human to approve them. The rules don’t wait on any of that.

Then there was the file we actually had to hand over.

Workday’s exports were .txt files with CSV inside and property values that looked almost, but not quite, like JSON. The destination needed a corrected index. Getting the categories right was worthless if that index didn’t survive the importer.

So the writer keeps the source formatting and swaps only the document-type value. The parser finds that property by its key, so it doesn’t care if the columns move. Tests cover line endings, quoting, reordered properties, and mismatched headers in the merged output. Reviewer changes get stable record hashes and an audit trail.

This is the part of the job I enjoy most. You get close enough to a scary-sized problem that it stops being scary and turns into a list of specific things to fix. Here, that list included a filing rule, somebody’s name, and the exact shape of a text file.

Leaving Workday was decided at the top. Getting years of documents into Banner in usable shape came down to the details in an export. I’m glad we looked closely enough to build it ourselves.
