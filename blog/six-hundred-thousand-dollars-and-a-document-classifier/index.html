$600k saved with a document classifier

A million-document migration. Python rules, careful redaction, and an index the destination system could actually use.

12 Sep, 2026

I built classification software for a million-document Workday-to-Banner migration at Indian River State College. The saving: $600,000.

The useful part of the story is how much of the job ordinary Python could do.

Workday exported documents under broad categories. Banner’s document-management system needed more specific types. A bucket called “Admission Documents” didn’t tell the destination system where each record belonged.

The job was to turn the information already in the export into an index the importer could use.

Those index files had a .txt extension, CSV contents, and property cells that looked almost like JSON. Almost is where parsers get interesting. The code finds properties by their keys, so moving DOCUMENT-TYPE to another column doesn’t silently change what the program reads.

Then come the classification rules: approved phrases, normalized separators, explicit destinations. When the filename supports a decision, Python makes it. Conflicting evidence goes to an approved fallback.

One small detail mattered: DE could mean Dual Enrollment, while “De” could be part of somebody’s name. A loose substring match would turn a person’s name into a filing decision. The pipeline masks known names and IDs before matching, including names collected across the input corpus.

The documented validation run covered 1,887 index rows. It assigned 1,396 to specific document types and 491 to an approved Legacy Document destination. That is sample coverage, not a million-document accuracy benchmark. The default run made no LLM calls.

I added an optional model path for unresolved rows. It can use Ollama locally or an explicitly enabled cloud backend. Both require redacted inputs. Model suggestions go into a review queue; a human has to approve them before they become mappings.

The part I cared about just as much was the output. Correct classification is useless if the importer rejects the file.

The writer preserves each source index’s formatting while changing the document-type value. Tests cover line endings, quoting, reordered properties, and merged files with different columns. Every run also produces an audit trail, a configuration snapshot, and review files. Reviewer decisions are matched by stable record hashes.

This is the kind of software I like building. A specific operational problem, a narrow tool, and a result someone can use. The interesting question was how little machinery the job actually needed.
