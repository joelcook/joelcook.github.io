$47k saved. Then I worked on the answers.

Replacing a legacy chatbot, handling 9,000+ weekly chats, and building the knowledge layer behind the answers.

23 Jun, 2026 · updated 12 Sep, 2026

I replaced a legacy chatbot at Indian River State College with an AI assistant. $47,000 saved. More than 9,000 chats a week.

A lower bill is a useful start. Students still need the right answers.

A question about tuition or a drop deadline looks simple. The answer changes by term, and an old page can sound just as authoritative as a current one. Giving a model more text doesn’t settle which source it should trust.

I built the knowledge layer around a split: changing facts in SQLite, explanations in a source-cited wiki.

Tuition, deadlines, contacts, and course information come from database tools. “How do I apply?” gets guidance from the wiki. The assistant can explain the process while looking up the details that change.

The data starts with official sources. Scrapers capture those pages, a build projects structured facts into SQLite, and the wiki holds compiled explanations with source lineage. The refresh job rebuilds the data. Wiki rewrites and Azure deployments are separate steps, so a successful scrape doesn’t silently publish everything else.

The serving interface is 12 read-only MCP tools on Azure Container Apps, connected to Microsoft Copilot Studio. That gives the assistant named operations such as get_deadline, get_tuition, and search_wiki.

The wiki search is small enough to run inside the Python process. It scores curated pages using words, headings, and domain synonyms. I kept the default path free of a separate search-model download and a subprocess on every request. A small corpus lets you make those choices.

Call the pattern agentic RAG or an LLM wiki. The part worth explaining is what happens when the assistant gets something wrong.

The evaluation set now has 53 cases. It checks answers, required tool calls, source conflicts, and questions about private student records that the public assistant should refuse. An answer with the right tuition figure still fails if the required lookup never happened.

There’s an optional LLM judge for narrative answers. Deterministic checks run first. A second model’s opinion doesn’t replace an assertion I can check directly.

That distinction showed up in a Copilot Studio evaluation. Its general-quality judge marked correct privacy refusals as incomplete answers. The review also found a deployment problem: a new Azure revision had failed to start, leaving the old one serving traffic. Those failures needed different fixes.

The local tools gate checks the database and tool behavior without paying for inference. Testing the production model is a separate job. A green local check cannot tell me that a hosted model followed the instructions.

I can test the retrieval path, inspect the sources, and catch known regressions. I cannot promise that a language model will never invent an answer. The value of this architecture is that a wrong answer gives me specific things to investigate.

The replacement saved $47k. The engineering work is keeping the system worth using after the information changes.
